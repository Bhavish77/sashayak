# Glossary

Plain-language definitions for domain and technical terms, added the first time each one appears in the implementation. This file is public, so keep wording neutral.

| Term                | Means                                                                                                                                                                                                                                                                                                |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Minor units (paise) | The smallest unit of a currency — for INR, paise (1 rupee = 100 paise). All amounts are stored and computed as whole-number paise, never as a rupee amount with a decimal point, so rounding errors in binary floating point can never creep into a balance.                                         |
| Hold                | Money set aside in a wallet for a transfer that hasn't finished yet: moved out of "available" into "held," but not yet actually paid out. A hold is later either settled (money leaves for good) or released (money returns to available) — never both.                                              |
| Branded type        | A plain string or number (like a UUID) wrapped with a compile-time-only tag so a `TransferId` and a `UserId` can't be mixed up by accident, even though they're both just strings at runtime. The tag exists only for the type checker; it adds nothing to what's stored or sent over the network.   |
| problem+json        | A standard shape for API error responses (RFC 9457): every error comes back with the same fields (`type`, `title`, `status`, a short machine-readable `code`, a human `detail`, and the `request_id` to quote when asking for help), instead of each error inventing its own shape.                  |
| Event envelope      | The fixed wrapper every event shares (who sent it, when, a dedup id, trace info) around a payload whose own shape is specific to that event's type. Services read the envelope the same way regardless of what happened; only the payload changes meaning.                                           |
| Canonical JSON      | A single, fixed way of turning a value into text — keys always in the same order, no extra spaces — so the same logical fact always produces the exact same bytes. Needed before hashing something (like an audit entry), since a hash is only useful if equal facts always hash identically.        |
| Access matrix       | A table saying exactly which service may call which internal route. Anything not listed is refused by default, so the list doubles as the one place that answers "who can talk to whom."                                                                                                             |
| Contract fake       | A stand-in for a real network call to another service, built directly from that route's own request/response rules: it rejects bad input and bad output the same way the real service would, so tests can catch a broken contract without needing the real service running.                          |
| Redaction           | Replacing personal data (a phone number, email, account number) with a fixed placeholder like `[PHONE]` before it ever reaches a log, trace or stored record. Amounts are deliberately never touched, since they're the one kind of number this system needs to keep reading.                        |
| Luhn check          | A simple checksum built into real card numbers: multiply every second digit by two (and subtract 9 if that goes over 9), add everything up, and the total must end in 0. It's how "looks like a card number" is told apart from "is shaped like one but isn't," without needing a real card network. |
| Fail closed         | When something goes wrong in a safety check, the safe-but-unhelpful outcome happens instead of the original, unchecked one. For redaction, that means a value that could not be safely checked becomes a fixed "redaction failed" marker, never the original, possibly sensitive value — the opposite of "fail open," where a broken check would let the original value through. |
